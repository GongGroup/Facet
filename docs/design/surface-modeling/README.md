# 表面建模功能设计（Surface modeling）

本目录是 Crystallume 表面建模功能的设计文档，供开发团队（多个开发代理）按此实现。文档用中文写，标识符、文件路径和界面文案用英文。

## 目标

补齐"体相 → 切面 → slab → 固定底层 → 放吸附物 → 导出计算文件"这条建模链，覆盖 Materials Studio 在表界面建模上的功能，
并补上 MS 没有、做催化课题常常要手工绕过去的几项：终止面列表、最小表面网格、吸附位点识别、按层和按高度选原子、非对角超胞预设、自动晶格匹配。

## 用户已定的决定（最高优先级，详见 `00-architecture.md` 的 U 节）

- **U1** 导入时识别 slab 要做，但要无感：不弹提示、不改 pbc、不改导出的文件；只在内部检测真空间隙，用于显示（不再在真空顶部重复画底层原子、跨晶胞边界的 slab 不被拆开）、层分析和吸附位点判断上下表面。slab 和非 slab 不做其他区分。
- **U2** Crystallume 生成的 slab 保持三维周期（pbc T T T），标准取向：a 沿 x，c 垂直于表面。
- **U3** 界面与异质结（M6）纳入本期，第 4 波开发。
- **U4** 不设默认真空：界面里必须填写，API 和命令行里是必填参数；真空一律指总间隙。其余默认值：4 层、六方表面网格 120°、slab 居中。
- **U5** 其余按推荐：新增 Surface 面板；放吸附物原位修改；extxyz 用 ASE 的 `move_mask`；影响新功能的现有缺陷先修。
- **U6** 设计完成后直接开发。

## 开发方式

- 负责人（主会话）负责排期、集成和最终决定；开发代理各自在独立的 git worktree 和本地分支上实现一个任务，按规格的"开发拆分"一节划定文件归属，避免冲突。
- 每个小批次结束后：集成代理按规格给出的合并顺序合并、解决冲突、跑完整测试（Python 全套 + Node 单元与跨语言用例），然后推送到 `claude/clever-thompson-5wtccp`。
- 每一波结束后：领域审查、工程审查和界面审查三个代理对整波的改动做对抗审查，修复代理处理确认的问题，再推送。
- 浏览器端用预装的 Chromium 和 Playwright 做冒烟测试和截图检查。
